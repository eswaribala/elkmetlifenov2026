Exercise 2 file beat to logstash

Step 1 — Create the log directory
  Run on the Ubuntu machine where Filebeat is installed.
  sudo mkdir -p /var/log/elastic-lab
  sudo chmod 755 /var/log/elastic-lab

Step 2 — Create a simple log file
Create app.log containing INFO, WARN, and ERROR messages.
sudo nano /var/log/elastic-lab/app.log
#add the following
2026-11-03 10:00:00 INFO Application started
2026-11-03 10:01:00 WARN Memory usage high
2026-11-03 10:02:00 ERROR Database connection failed
2026-11-03 10:03:00 INFO User login successful
2026-11-03 10:04:00 ERROR Payment failed

Set read permissions:
sudo chmod 644 /var/log/elastic-lab/app.log

Verify:
cat /var/log/elastic-lab/app.log

Step 3 — Configure Filebeat
Open:
sudo nano /etc/filebeat/filebeat.yml

Find the existing filebeat.inputs section and configure it as follows:
filebeat.inputs:
  - type: filestream
    id: elastic-lab
    enabled: true
    paths:
      - /var/log/elastic-lab/*.log

Enable the Logstash output:
output.logstash:
  hosts: ["127.0.0.1:5044"]

sudo nano /etc/logstash/conf.d/filebeat.conf

input {
  beats {
    host => "0.0.0.0"
    port => 5044
  }
}

filter {
}

output {
  stdout {
    codec => rubydebug
  }

  file {
    path => "/var/log/logstash/elastic-lab-received.log"
    codec => line {
      format => "%{message}"
    }
  }
}

Step 5 — Test and start Logstash
Validate the pipeline:
sudo chown -R logstash:logstash /var/log/logstash
sudo chmod 750 /var/log/logstash

sudo -u logstash /usr/share/logstash/bin/logstash --path.settings /etc/logstash -t
Restart Logstash:
sudo systemctl restart logstash


Check status:
sudo systemctl status logstash

Step 6 — Start Filebeat
Return to the Filebeat machine.

Validate its configuration:
sudo filebeat test config

sudo systemctl restart filebeat


Check status:
sudo systemctl status filebeat

Test connectivity to Logstash:
sudo filebeat test output

run new log
for i in $(seq 1 10); do
  echo "$(date '+%F %T') INFO Application request=$i"
done | sudo tee -a /var/log/elastic-lab/app.log

Step 7 — Verify logs received by Logstash
On the Logstash server:
sudo tail -f /var/log/logstash/elastic-lab-received.log

Step 8 — Test real-time ingestion
On the Filebeat server, append a new log entry:
echo "$(date '+%F %T') ERROR Payment failed" \
  | sudo tee -a /var/log/elastic-lab/app.log

On the Logstash server, check again:
sudo tail -n 10 /var/log/logstash/elastic-lab-received.log

exercise 3 logstash to elastic

check kibana
sudo grep -nE '^[[:space:]]*(elasticsearch.hosts|elasticsearch.ssl.certificateAuthorities|elasticsearch.ssl.verificationMode):' /etc/kibana/kibana.yml

Step 1 — Download the corrected files
I prepared the updated configuration and cleaned CSV for your Ubuntu lab.
Cleaned CSV file

10 records, Ubuntu-compatible line endings

tmax11_ubuntu.csv

Recommended: HTTPS configuration

For Elasticsearch with TLS and authentication enabled

tmax11_ubuntu_https.conf

Alternative: HTTP configuration

Only for Elasticsearch configured without authentication or TLS

tmax11_ubuntu_http.conf

Step 2 — Create the CSV lab directory
On es-node1:
sudo mkdir -p /opt/elastic-lab/csv


Copy your downloaded CSV:
sudo cp ~/Downloads/tmax11_ubuntu.csv /opt/elastic-lab/csv/tmax11.csv

For the usual secured Elasticsearch installation, copy the HTTPS configuration:
sudo cp ~/Downloads/tmax11_ubuntu_https.conf /opt/elastic-lab/csv/tmax11.conf

Set permissions:
sudo chmod 755 /opt/elastic-lab /opt/elastic-lab/csv
sudo chmod 644 /opt/elastic-lab/csv/tmax11.*

Verify:
cat /opt/elastic-lab/csv/tmax11.csv
wc -l /opt/elastic-lab/csv/tmax11.csv

Step 3 — Verify Elasticsearch connectivity
Since you already have Elasticsearch on es-node1, check whether it uses HTTPS.

For the default secured installation:
sudo curl --cacert /etc/elasticsearch/certs/http_ca.crt \
  -u elastic https://localhost:9200

Step 4 — Prepare HTTPS security (if using the HTTPS file)
Copy the Elasticsearch CA certificate into a location accessible to Logstash:
sudo mkdir -p /etc/logstash/certs
sudo install -m 644 /etc/elasticsearch/certs/http_ca.crt \
  /etc/logstash/certs/http_ca.crt

Step 5 — Create a separate Logstash data directory
This avoids conflicts with your running Filebeat → Logstash service.
sudo install -d -o logstash -g logstash -m 750 /var/lib/logstash-csv

Step 6 — Execute the CSV pipeline
For the HTTPS configuration, first enter your Elasticsearch password without displaying it:
read -rsp "Elasticsearch password: " ES_PASSWORD
echo

Validate:
sudo -u logstash env ES_PASSWORD="$ES_PASSWORD" \
  /usr/share/logstash/bin/logstash \
  --path.settings /etc/logstash \
  --path.data /var/lib/logstash-csv \
  --api.http.port 9601 \
  -f /opt/elastic-lab/csv/tmax11.conf \
  --config.test_and_exit

Now execute the pipeline by removing --config.test_and_exit:
sudo -u logstash env ES_PASSWORD="$ES_PASSWORD" \
  /usr/share/logstash/bin/logstash \
  --path.settings /etc/logstash \
  --path.data /var/lib/logstash-csv \
  --api.http.port 9601 \
  -f /opt/elastic-lab/csv/tmax11.conf

Step 7 — Verify documents in Elasticsearch
Open another Ubuntu terminal.

For HTTPS:
sudo curl --cacert /etc/elasticsearch/certs/http_ca.crt \
  -u elastic \
  'https://localhost:9200/csv-stock-data/_count?pretty'
